## Setup

Install Motherload, then add it to TypeScript and to each tool that loads your code.

### Install

You'll need:

- **TypeScript 7.1 (currently in beta).** The first release with content mappers.
- **Node 24 or later.**

```sh
npm install -D motherload typescript@beta
```

If your app runs under the preload, not as a bundle, Motherload loads your data files at run time, so install it as a dependency:

```sh
npm install motherload
npm install -D typescript@beta
```

### TypeScript

Add Motherload to `tsconfig.json`, listing the extensions you import:

```jsonc title="tsconfig.json"
{
  "compilerOptions": { /* ... */ },
  "contentMappers": [ // [!code ++]
    { // [!code ++]
      "package": "motherload", // [!code ++]
      "extensions": [ // [!code ++]
        ".toml", ".yaml", ".yml", ".jsonc", ".json5", ".env", // [!code ++]
        ".csv", ".tsv", ".txt", ".md" // [!code ++]
      ] // [!code ++]
    } // [!code ++]
  ] // [!code ++]
}
```

Then type-check with `--runExternalCode`, which lets `tsc` run content mappers:

```jsonc title="package.json"
{
  "scripts": {
    "typecheck": "tsc --noEmit --runExternalCode" // [!code ++]
  }
}
```

### Plugins

Install the plugin for your runtime or framework of choice:

<Tabs items={["Node", "Bun", "Nub", "Vite", "Next.js", "esbuild", "webpack", "Rspack", "Cloudflare", "Jest"]}>
<Tab value="Node" id="setup-node">

Load Motherload's preload with `--import`:

```sh
node --import motherload/register main.ts
```

</Tab>
<Tab value="Bun" id="setup-bun">

Add the preload to `bunfig.toml`, and under `[test]` for `bun test`:

```toml title="bunfig.toml"
preload = ["motherload/register"]

[test]
preload = ["motherload/register"]
```

For Bun's bundler, use the esbuild plugin:

```ts title="build.ts"
import motherload from "motherload/esbuild";

await Bun.build({
  entrypoints: ["main.ts"],
  target: "bun",
  plugins: [motherload()],
  outdir: "dist",
});
```

</Tab>
<Tab value="Nub" id="setup-nub">

Add the preload to `nub.jsonc`:

```jsonc title="nub.jsonc"
{
  "preload": ["motherload/register"]
}
```

</Tab>
<Tab value="Vite" id="setup-vite">

```ts title="vite.config.ts"
import { defineConfig } from "vite";
import motherload from "motherload/vite";

export default defineConfig({
  plugins: [motherload()],
});
```

For Vitest, this plugin is all you need. Rollup and Rolldown take it too:

```js title="rollup.config.mjs"
import motherload from "motherload/vite";

export default {
  // ...
  plugins: [motherload()],
};
```

</Tab>
<Tab value="Next.js" id="setup-nextjs">

Wrap your Next.js config with `withMotherload`:

```ts title="next.config.ts"
import type { NextConfig } from "next";
import { withMotherload } from "motherload/next";

const nextConfig: NextConfig = {
  // ...
};

export default withMotherload(nextConfig);
```

Your server and client components can now import every format but `.env`, which Next.js loads itself, with Turbopack or webpack, and `next build` fails on a type error in a data file's caller.

To type-check without building, run `next typegen` first, which writes the route types:

```json title="package.json"
{
  "scripts": {
    "typecheck": "next typegen && tsc --noEmit --runExternalCode"
  }
}
```

<Details summary="How the build checks the types" id="nextjs-type-check">

Next.js type-checks with your project's `tsc` but without `--runExternalCode`, so `withMotherload` turns that check off and runs `tsc --noEmit --runExternalCode` itself, after the compile and before the prerender. Next.js still prints "Skipping validation of types" for its own check.

</Details>

</Tab>
<Tab value="esbuild" id="setup-esbuild">

```js title="build.mjs"
import * as esbuild from "esbuild";
import motherload from "motherload/esbuild";

await esbuild.build({
  entryPoints: ["main.ts"],
  bundle: true,
  platform: "node",
  format: "esm",
  plugins: [motherload()],
  outfile: "dist/main.mjs",
});
```

</Tab>
<Tab value="webpack" id="setup-webpack">

```js title="webpack.config.mjs"
export default {
  // ...
  module: {
    rules: [
      {
        test: /\.(toml|ya?ml|jsonc|json5|env|[ct]sv|txt|md)$/,
        use: "motherload/webpack",
      },
    ],
  },
};
```

Compile TypeScript with `swc-loader` or `babel-loader`, since TypeScript 7 has no JavaScript API for `ts-loader`.

</Tab>
<Tab value="Rspack" id="setup-rspack">

```js title="rspack.config.mjs"
export default {
  // ...
  module: {
    rules: [
      {
        test: /\.(toml|ya?ml|jsonc|json5|env|[ct]sv|txt|md)$/,
        use: "motherload/webpack",
      },
    ],
  },
};
```

</Tab>
<Tab value="Cloudflare" id="setup-cloudflare-workers">

Add Motherload's Vite plugin beside Cloudflare's:

```ts title="vite.config.ts"
import { cloudflare } from "@cloudflare/vite-plugin";
import { defineConfig } from "vite";
import motherload from "motherload/vite";

export default defineConfig({
  plugins: [motherload(), cloudflare()],
});
```

Deploy with `wrangler deploy` after `vite build`: Wrangler's own bundler takes no plugin.

</Tab>
<Tab value="Jest" id="setup-jest">

Add Motherload's transformer to your Jest config:

```js title="jest.config.js"
export default {
  transform: {
    "\\.(toml|ya?ml|jsonc|json5|env|[ct]sv|txt|md)$": "motherload/jest",
  },
  extensionsToTreatAsEsm: [
    ".toml", ".yaml", ".yml", ".jsonc", ".json5", ".env",
    ".csv", ".tsv", ".txt", ".md",
  ],
};
```

```sh
# Jest runs ES modules only behind this Node flag
NODE_OPTIONS=--experimental-vm-modules npx jest
```

</Tab>
</Tabs>

### Editors

Set up your editor to use the TypeScript 7.1 language server, with content mappers on.

<Tabs items={["VS Code", "Cursor", "Zed"]}>
<Tab value="VS Code" id="editor-vscode">

1. Install the **TypeScript 7** extension (`TypeScriptTeam.native-preview`).
2. Point it at the project's TypeScript: the extension's own copy is TypeScript 7.0, which has no content mappers.

   ```json title=".vscode/settings.json"
   {
     "js/ts.experimental.useTsgo": true,
     "js/ts.tsdk.path": "./node_modules/typescript"
   }
   ```

3. Trust the workspace, and click **Allow** when the extension asks to use the workspace's TypeScript. Content mappers run in a trusted workspace only.

</Tab>
<Tab value="Cursor" id="editor-cursor">

1. Install the **TypeScript 7** extension (`TypeScriptTeam.native-preview`).
2. Point it at the project's TypeScript: the extension's own copy is TypeScript 7.0, which has no content mappers.

   ```json title=".vscode/settings.json"
   {
     "js/ts.experimental.useTsgo": true,
     "js/ts.tsdk.path": "./node_modules/typescript"
   }
   ```

3. Trust the workspace, and click **Allow** when the extension asks to use the workspace's TypeScript. Content mappers run in a trusted workspace only.

</Tab>
<Tab value="Zed" id="editor-zed">

1. Install the **TypeScript Language Server** extension by Zed Industries (search for "tsgo").
2. Point it at the project's TypeScript, with content mappers on:

   ```jsonc title=".zed/settings.json"
   {
     "languages": {
       "TypeScript": {
         "language_servers": [
           "typescript-ls",
           "!vtsls",
           "!typescript-language-server",
           "..."
         ]
       },
       "TSX": {
         "language_servers": [
           "typescript-ls",
           "!vtsls",
           "!typescript-language-server",
           "..."
         ]
       }
     },
     "lsp": {
       "typescript-ls": {
         // the extension's own download is TypeScript 7.0, which has no content mappers
         "binary": {
           "path": "node_modules/typescript/bin/tsc",
           "arguments": ["--lsp", "--stdio"]
         },
         "initialization_options": { "runExternalCode": true }
       }
     }
   }
   ```

3. Trust the folder. In restricted mode, Zed starts no language server.

Zed doesn't send data files to the language server, so an error inside one shows only in the type check.

</Tab>
</Tabs>

### Loaders à la carte [#loaders-a-la-carte]

The `motherload` package provides one unified content mapper for all data formats. You can also consume them à la carte.

| Package | Extensions |
| --- | --- |
| `@motherload/toml` | `.toml` |
| `@motherload/yaml` | `.yaml`, `.yml` |
| `@motherload/jsonc` | `.jsonc` |
| `@motherload/json5` | `.json5` |
| `@motherload/env` | `.env` |
| `@motherload/csv` | `.csv`, `.tsv` |
| `@motherload/txt` | `.txt` |
| `@motherload/md` | `.md` |

Each one is set up as `motherload` is, under its own name. A project that reads YAML and TOML:

```sh
npm install -D @motherload/yaml @motherload/toml
```

```jsonc title="tsconfig.json"
{
  "contentMappers": [ // [!code ++]
    { "package": "@motherload/yaml", "extensions": [".yaml", ".yml"] }, // [!code ++]
    { "package": "@motherload/toml", "extensions": [".toml"] } // [!code ++]
  ] // [!code ++]
}
```

```sh tab="Node"
node --import @motherload/yaml/register \
  --import @motherload/toml/register main.ts
```

```js tab="esbuild"
import * as esbuild from "esbuild";
import yaml from "@motherload/yaml/esbuild";
import toml from "@motherload/toml/esbuild";

await esbuild.build({
  entryPoints: ["main.ts"],
  bundle: true,
  platform: "node",
  format: "esm",
  plugins: [yaml(), toml()],
  outfile: "dist/main.mjs",
});
```

```ts tab="Vite"
import { defineConfig } from "vite";
import yaml from "@motherload/yaml/vite";
import toml from "@motherload/toml/vite";

export default defineConfig({
  plugins: [yaml(), toml()],
});
```

```ts tab="Next.js"
const nextConfig: NextConfig = {
  turbopack: {
    rules: {
      "*.{yaml,yml}": {
        loaders: ["@motherload/yaml/turbopack"],
        as: "*.js",
      },
      "*.toml": {
        loaders: ["@motherload/toml/turbopack"],
        as: "*.js",
      },
    },
  },
};
```

```js tab="webpack"
export default {
  module: {
    rules: [
      { test: /\.ya?ml$/, use: "@motherload/yaml/webpack" },
      { test: /\.toml$/, use: "@motherload/toml/webpack" },
    ],
  },
};
```

List each extension once, under `motherload` or under its own package: two packages that claim one extension fail the type check.

## Setup

Install Motherload and TypeScript 7.1:

```sh
npm install -D motherload typescript@beta
```

<Callout>Motherload is powered by [content mappers](https://github.com/microsoft/typescript-go/pull/4712), a new feature of TypeScript 7.1. TypeScript 7.1 is currently in beta.</Callout>

Motherload needs Node 24 or later. An app that runs under the preload, not as a bundle, loads Motherload at run time, so it lists `motherload` in `dependencies`.

### TypeScript

Add Motherload to `tsconfig.json`, with the extensions it should own.

```jsonc title="tsconfig.json"
{
  "contentMappers": [ // [!code ++]
    { // [!code ++]
      "package": "motherload", // [!code ++]
      "extensions": [ // [!code ++]
        ".toml", ".yaml", ".yml", ".jsonc", ".json5", ".env", // [!code ++]
        ".csv", ".tsv", ".txt", ".md" // [!code ++]
      ] // [!code ++]
    } // [!code ++]
  ] // [!code ++]
}
```

Type-check with `--runExternalCode`. Without the flag, `tsc` ignores content mappers.

```json title="package.json"
{
  "scripts": {
    "typecheck": "tsc --noEmit --runExternalCode"
  }
}
```

### Editors

The editor needs the TypeScript 7.1 language server, with content mappers on.

<Accordions type="multiple">
<Accordion title="VS Code" id="editor-vscode">

1. Install the **TypeScript 7** extension (`TypeScriptTeam.native-preview`).
2. Point it at the project's TypeScript: the extension's own copy is TypeScript 7.0, which has no content mappers.

   ```json title=".vscode/settings.json"
   {
     "js/ts.experimental.useTsgo": true,
     "js/ts.tsdk.path": "./node_modules/typescript"
   }
   ```

3. Trust the workspace, and click **Allow** when the extension asks to use the workspace's TypeScript. Content mappers run in a trusted workspace only.

To suggest the extension to everyone who opens the project:

```json title=".vscode/extensions.json"
{ "recommendations": ["TypeScriptTeam.native-preview"] }
```

</Accordion>

<Accordion title="Zed" id="editor-zed">

1. Install the **TypeScript Language Server** extension by Zed Industries (search for "tsgo").
2. Point it at the project's TypeScript, with content mappers on:

   ```jsonc title=".zed/settings.json"
   {
     "languages": {
       "TypeScript": {
         "language_servers": [
           "typescript-ls",
           "!vtsls",
           "!typescript-language-server",
           "..."
         ]
       },
       "TSX": {
         "language_servers": [
           "typescript-ls",
           "!vtsls",
           "!typescript-language-server",
           "..."
         ]
       }
     },
     "lsp": {
       "typescript-ls": {
         // the extension's own download is TypeScript 7.0, which has no content mappers
         "binary": {
           "path": "node_modules/typescript/bin/tsc",
           "arguments": ["--lsp", "--stdio"]
         },
         "initialization_options": { "runExternalCode": true }
       }
     }
   }
   ```

3. Trust the folder. In restricted mode, Zed starts no language server.

After a change to `binary.path`, close the window and open it again. In a monorepo whose TypeScript is installed at the root, `binary.path` points at that copy.

### Node

Node loads Motherload with `--import`, which turns each data file into a module as it loads:

```sh
node --import motherload/register main.ts
```

### Plugins

Everywhere else, a plugin turns each data file into a module: Nub loads Motherload's preload from its config file, and a bundler builds each module at build time, so a bundled app needs no `--import` and no preload, and Motherload stays a development dependency.

<Accordions type="multiple">
<Accordion title="Nub" id="setup-nub">

Nub takes the preload in `nub.jsonc`, so `nub main.ts` needs no flag:

```jsonc title="nub.jsonc"
{
  "preload": ["motherload/register"]
}
```

</Accordion>
<Accordion title="esbuild" id="setup-esbuild">

```js title="build.mjs"
import * as esbuild from "esbuild";
import motherload from "motherload/esbuild";

await esbuild.build({
  entryPoints: ["main.ts"],
  bundle: true,
  platform: "node",
  format: "esm",
  plugins: [motherload()],
  outfile: "dist/main.mjs",
});
```

Use `.build()`: esbuild runs plugins in `.build()` only, and `.buildSync()` throws.

</Accordion>
</Accordions>

### Loaders à la carte [#loaders-a-la-carte]

The `motherload` package provides one unified content mapper for all data formats. You can also consume them à la carte.

| Package | Extensions |
| --- | --- |
| `@motherload/toml` | `.toml` |
| `@motherload/yaml` | `.yaml`, `.yml` |
| `@motherload/jsonc` | `.jsonc` |
| `@motherload/json5` | `.json5` |
| `@motherload/env` | `.env` |
| `@motherload/csv` | `.csv`, `.tsv` |
| `@motherload/txt` | `.txt` |
| `@motherload/md` | `.md` |

Each one is set up as `motherload` is, under its own name. A project that reads YAML and TOML:

```sh
npm install -D @motherload/yaml @motherload/toml
```

```jsonc title="tsconfig.json"
{
  "contentMappers": [ // [!code ++]
    { "package": "@motherload/yaml", "extensions": [".yaml", ".yml"] }, // [!code ++]
    { "package": "@motherload/toml", "extensions": [".toml"] } // [!code ++]
  ] // [!code ++]
}
```

```sh tab="Node"
node --import @motherload/yaml/register \
  --import @motherload/toml/register main.ts
```

```js tab="esbuild"
import * as esbuild from "esbuild";
import yaml from "@motherload/yaml/esbuild";
import toml from "@motherload/toml/esbuild";

await esbuild.build({
  entryPoints: ["main.ts"],
  bundle: true,
  platform: "node",
  format: "esm",
  plugins: [yaml(), toml()],
  outfile: "dist/main.mjs",
});
```

List each extension once, under `motherload` or under its own package: two packages that claim one extension fail the type check.

Motherload is a set of TypeScript loaders for data formats: import a TOML, YAML, JSON5, JSONC, CSV, TSV, Markdown, text or `.env` file, or a JSON Schema, and get a typed module.

<p className="ml-lede">It's powered by TypeScript's [_content mappers_](https://github.com/microsoft/typescript-go/pull/4712) (introduced typescript@7.1). These are like plugins for TypeScript, and it lets Motherload provide _full static types_ for the imported data, in a way that natively integrates with `tsc`.</p>

```ts twoslash tab="main.ts"
declare const input: unknown;
// ---cut---
import plans from "./plans.toml";
import team from "./team.yaml";
import strings from "./strings.json5";
import posts from "./posts.csv";
import notes, { frontmatter } from "./notes.md";
import "./.env";
import user from "./user.schema.json";

plans.pro.price;
team[0].role;
strings.welcome;
posts[0].title;
frontmatter.tags;
process.env.DATABASE_URL;
user.parse(input);
```

```toml tab="plans.toml"
seats = 1

```


Hover over a name to see its type. Each type comes from the file, in the type check and in the editor, and the same imports run under Node.js, Nub and esbuild.

## How it works

The type check and the editor run Motherload as a content mapper: TypeScript hands it each data file a project imports, and it returns the module's types. At run time, a preload or a bundler plugin turns the same file into a module.

```text
plans.toml  →  Motherload  →  { readonly free: { readonly price: 0; readonly seats: 1 }; readonly pro: { … } }
```

## Setup

Install Motherload, add it to `tsconfig.json`, then add it to each tool that loads your code.

### Install

```sh
npm install -D motherload
npm install -D typescript@next   # content mappers are in the TypeScript 7.1 dev builds
```

Schema imports need three optional peer dependencies, which run only when a module is built:

```sh
npm install -D json-schema-to-typescript ajv ajv-formats
```

The package needs Node 24 or later. An application that runs under the preload instead of a bundle loads Motherload at run time, so it lists `motherload` in `dependencies`.

### TypeScript

Add Motherload to `tsconfig.json`, with the extensions it should own. The `types` entry types `?raw` imports.

```jsonc title="tsconfig.json"
{
  "compilerOptions": {
    "types": ["motherload/client"] // [!code ++]
  },
  "contentMappers": [ // [!code ++]
    { "package": "motherload", "extensions": [".toml", ".yaml", ".yml", ".json5", ".jsonc", ".env", ".csv", ".tsv", ".txt", ".md", ".schema.json"] } // [!code ++]
  ] // [!code ++]
}
```

Type-check with `--runExternalCode`. Without the flag, `tsc` ignores content mappers.

```json title="package.json"
{
  "scripts": {
    "typecheck": "tsc --noEmit --runExternalCode"
  }
}
```

### Runtimes

A preload turns each data file into a module as it loads. Node.js takes it with `--import`:

```sh
node --import motherload/register main.ts
```

Nub reads the preload from `nub.jsonc`, so no flag is needed:

```jsonc title="nub.jsonc"
{
  "preload": ["motherload/register"]
}
```

### Bundlers

A bundler plugin turns each data file into a module at build time, so a bundled app needs no preload, and Motherload stays a development dependency.

<Accordions type="multiple">
<Accordion title="esbuild" id="setup-esbuild">

```js title="build.mjs"
import * as esbuild from "esbuild";
import motherload from "motherload/esbuild";

await esbuild.build({
  entryPoints: ["main.ts"],
  bundle: true,
  plugins: [motherload()],
  outfile: "dist/main.js",
});
```

</Accordion>
</Accordions>

## Loaders

A loader turns a file into a module. Each file is parsed when the module is built, so a bundle holds the data as an object literal and no parser.

The default export is the file's data, typed as `as const` would type it:

```ts twoslash title="main.ts"
import plans from "./plans.toml";

const pro = plans.pro;
//    ^?
```

Add `?raw` to an import for the file's text:

```ts twoslash title="main.ts"
import text from "./plans.toml?raw";
//     ^?
```

### `.toml`

Motherload reads TOML 1.1 with [smol-toml](https://github.com/squirrelchat/smol-toml). TOML has four kinds of date. Only an offset date-time names an instant, so only that one becomes a `Date`:

```toml title="release.toml"
published = 1979-05-27T07:32:00Z   # offset date-time
day = 1979-05-27                   # local date
at = 07:32:00                      # local time
downloads = 9007199254740993       # past 2^53
ratio = inf
```

```ts twoslash title="main.ts"
import release from "./release.toml";
//     ^?
```

A local date-time, date or time is its ISO text. An integer that a `number` cannot hold exactly is a `bigint`.

### `.yaml`

Motherload reads YAML 1.2 with [yaml](https://eemeli.org/yaml/), so `yes` is a string. Merge keys (`<<`) are read, and a duplicate key is an error. A `.yml` file is read the same way.

```yaml title="app.yaml"
defaults: &defaults
  retries: 3
  timeout: 1.5
production:
  <<: *defaults
  host: example.com
enabled: yes
```

```ts twoslash title="main.ts"
import app from "./app.yaml";

const production = app.production;
//    ^?
const enabled = app.enabled;
//    ^?
```

A file of several documents (`---`) is the list of them:

```yaml title="deploy.yaml"
kind: Service
---
kind: Deployment
replicas: 2
```

```ts twoslash title="main.ts"
import deploy from "./deploy.yaml";
//     ^?
```

### `.json5`

Motherload reads JSON5 with [json5](https://json5.org), the JSON5 project's own parser.

```json5 title="data.json5"
{
  unquoted: 'single quotes',
  hex: 0x10,
  limit: Infinity,
  list: [1, 2, 3,],
}
```

```ts twoslash title="main.ts"
import data from "./data.json5";
//     ^?
```

### `.jsonc`

Motherload reads JSON with comments with Microsoft's [jsonc-parser](https://github.com/microsoft/node-jsonc-parser). Comments and trailing commas are allowed.

```jsonc title="settings.jsonc"
{
  // the editor's font size
  "editor.fontSize": 14,
  "files.exclude": ["dist", "node_modules",],
}
```

```ts twoslash title="main.ts"
import settings from "./settings.jsonc";
//     ^?
```

### `.env`

Importing a `.env` file loads its variables into `process.env` when the module runs, and types each one as a `string`:

```sh title=".env"
DATABASE_URL=postgres://localhost/app
PORT=3000
```

```ts twoslash title="main.ts"
import "./.env";

const url = process.env.DATABASE_URL;
//    ^?
```

A variable the environment already sets keeps its value. No value from the file is in the module or in a bundle. A bundle reads the file from the working directory when it runs, and loads nothing if the file is absent.

The `.env` entry reaches a file named `.env` or ending in `.env`, such as `prod.env`. A file such as `.env.local` ends in `.local`, which the entry does not reach.

### `.csv`

Motherload reads CSV with [csv-parse](https://csv.js.org/parse/). The first row names the columns, and each later row is an object of strings keyed by them:

```csv title="users.csv"
name,email,zip
Ada Lovelace,ada@example.com,02134
"Hopper, Grace",grace@example.com,10001
```

```ts twoslash title="main.ts"
import users from "./users.csv";
//     ^?
```

Values stay as written, so a zip code such as `02134` keeps its leading zero. A quoted field can hold commas, doubled quotes and line breaks. Blank lines are skipped. A row whose field count differs from the header's is an error, as is an empty or repeated column name.

### `.tsv`

A `.tsv` file is read the same way, with a tab between fields. Quotes are ordinary characters, so a field is exactly the text between two tabs.

```tsv title="scores.tsv"
player	score
Ada	42
Grace	37
```

```ts twoslash title="main.ts"
import scores from "./scores.tsv";
//     ^?
```

### `.txt`

Importing a `.txt` file gives its text as a string.

```txt title="notes.txt"
Notes from the lab.
A second line.
```

```ts twoslash title="main.ts"
import notes from "./notes.txt";
//     ^?
```

### `.md`

The default export of a `.md` file is its Markdown body, without the frontmatter. The frontmatter is a named export, read and typed as a `.yaml` file is:

```md title="post.md"
---
title: Hello, Motherload
draft: false
tags: [data, types]
---
# Hello

The body of the post.
```

```ts twoslash title="main.ts"
import body, { frontmatter } from "./post.md";
//     ^?
const meta = frontmatter;
//    ^?
```

The frontmatter runs from a `---` first line to the next `---` line. A file without one exports `{}`. Pass the body to a Markdown renderer for HTML, and add `?raw` to the import for the whole file.

### `.schema.json`

A `.schema.json` file is a schema, not data. Its module is the type the schema describes and a validator for it.

```json title="user.schema.json"
{
  "$schema": "http://json-schema.org/draft-07/schema#",
  "type": "object",
  "properties": {
    "name": { "type": "string", "minLength": 1 },
    "email": { "type": "string", "format": "email" },
    "role": { "enum": ["admin", "member"] }
  },
  "required": ["name", "role"],
  "additionalProperties": false
}
```

```ts twoslash title="main.ts"
declare const input: unknown;
// ---cut---
import user, { type Type as User } from "./user.schema.json";

const ada = user.parse(input);       // or a TypeError listing every issue
//    ^?

user.is(input);                      // input is User
user["~standard"].validate(input);   // Standard Schema v1
user.schema;                         // the schema, as a literal type
```

The schema's type is always exported as `Type`. The validator is compiled by [ajv](https://ajv.js.org) when the module is built, so the module imports nothing at run time, and the default export works with any library that accepts a [Standard Schema](https://standardschema.dev). The types come from [json-schema-to-typescript](https://github.com/bcherny/json-schema-to-typescript).

- **Drafts:** 06, 07, 2019-09 and 2020-12, chosen by `$schema`.
- **Formats:** checked when `ajv-formats` is installed.
- **References:** a `$ref` within the file is followed; a `$ref` to another file or a URL is an error.

### `.json`

Plain `.json` stays TypeScript's own: a content mapper cannot claim it. Turn on `resolveJsonModule` to import it:

```ts
import pkg from "./package.json";
```

## Errors

A file that does not parse fails the type check at the line and column of the problem:

```toml title="config.toml"
port = 8080
host = "localhost"
port = 9090
```

```text
config.toml(3,1): error motherload1: Invalid TOML document: trying to redefine an already defined table or value
```

The import of a broken file is typed `any`, so its uses add no errors of their own. Under the preload or a bundler, the same problem stops the load with the same message.

| Code | Problem |
| --- | --- |
| `motherload1` | The file does not parse |
| `motherload2` | A value no module can carry, such as a YAML `!!binary` |
| `motherload3` | A file whose extension Motherload does not read |
| `motherload4` | The schema is not valid, or a peer dependency is missing |
| `motherload5` | An option in the `tsconfig.json` entry; Motherload takes none |
